ESP32 雙隊自動計分系統｜安裝說明
版本 v5｜三塊 ESP32 ＋ 天秤加倍規則｜給第一次接手的人閱讀
這是什麼
這是一套紅隊、藍隊的自動計分系統。球進球門時，FC-51 紅外線感測器會偵測到並自動加分。比賽資訊顯示在網頁上，用手機、平板或電腦連同一個 Wi-Fi 就能看。
• 選手看板：只顯示兩隊分數和倒數計時，適合投影或放大螢幕。
• 裁判頁面：開始比賽、記錄罰分、提前結算、重設。
• 比賽流程：等待中 → 進行中（倒數 150 秒）→ 時間到自動結算 → 裁判按「開始下一輪」才會清空重來。
• 最終分數 ＝ 得分 － 罰分次數（最低為 0）。
• 天秤加倍規則：某隊的天秤開關累計被按 2 次，該隊在接下來 10 秒內，每個進球算 2 分。
系統由三塊 ESP32 組成
因為兩個球門距離遠，感測器線不適合拉太長，所以拆成三塊板子，各自放在要偵測的位置附近，板子之間用 ESP-NOW 無線通訊（不需要路由器轉接）。

材料清單
• ESP32 開發板 × 3（使用型號：ESP32 DEV MODULE）
• FC-51 紅外線避障感測器 × 2
• 微動開關 × 2（型號 V-15 這類，有 COM、NO、NC 三支腳）
• 能傳資料的 USB 線 × 3（只能充電的線無法燒錄程式）
• 行動電源或 5V 1A 以上的 USB 電源 × 3（比賽現場供電用）
• 杜邦線若干
• 一個 2.4 GHz 的 Wi-Fi 分享器（ESP32 不支援 5 GHz）
• 看比賽資訊的手機、平板或電腦
軟體準備
1. 安裝 Arduino IDE（2.x 版）。
2. 開啟「檔案 → 偏好設定」，在「額外的開發板管理員網址」貼上： https://espressif.github.io/arduino-esp32/package_esp32_index.json
3. 開啟「工具 → 開發板 → 開發板管理員」，搜尋 esp32，安裝 Espressif Systems 出的 esp32。2.x 與 3.x 版本都支援。
4. 開發板選 ESP32 Dev Module。
5. 不需要另外安裝函式庫，程式用到的 WiFi、WebServer、ESP-NOW 都內建。
6. 如果接上板子後看不到序列埠（COM 埠），需要安裝 USB 驅動，多數板子是 CP210x 或 CH340。

安裝步驟（請依順序）
步驟 1：設定主機的 Wi-Fi
打開 ESP32_Score_Master.ino，找到最前面這兩行，改成現場 Wi-Fi 的名稱與密碼（必須是 2.4 GHz）：
const char* ssid = "你的Wi-Fi名稱";
const char* password = "你的Wi-Fi密碼";
步驟 2：燒錄主機，記下它的 MAC 位址
1. 把主機接上電腦，選對板子（ESP32 Dev Module）和序列埠，上傳 ESP32_Score_Master.ino。
2. 如果上傳卡在 Connecting，上傳時按住板子上的 BOOT 鍵，開始寫入後再放開。
3. 打開「序列埠監控視窗」，右下角速率選 115200，按一下板子上的 EN（重開機）鍵。
4. 你會看到類似這樣的訊息，請把它們記下來：
[重要] 主機 MAC 位址：1C:9D:C2:F8:AD:00
[重要] 填入節點：{0x1C, 0x9D, 0xC2, 0xF8, 0xAD, 0x00}
選手看板：http://192.168.x.x
裁判頁面：http://192.168.x.x/referee
• 「MAC 位址」是這塊主機板的身分號碼，每塊板子都不同。
• 「選手看板」和「裁判頁面」的網址就是之後要開啟的網頁。
• 如果 MAC 顯示全 0（00:00:00:00:00:00），代表程式不是最新版，請改用本包的 ESP32_Score_Master.ino。
步驟 3：把主機 MAC 填進另外兩塊板的程式
ESP32_Score_Node.ino 和 ESP32_Score_Switch.ino 裡都有這一行：
uint8_t MASTER_MAC[6] = {0x1C, 0x9D, 0xC2, 0xF8, 0xAD, 0x00};
• 檔案裡預設填的是原作者那塊主機的 MAC。如果你的主機板是另一塊，一定要改成步驟 2 印出的那一行「填入節點」。
• 填錯的話，節點和開關板永遠找不到主機，裁判頁面會一直顯示離線。
步驟 4：燒錄藍隊節點與天秤開關板
分別接上電腦，上傳 ESP32_Score_Node.ino 和 ESP32_Score_Switch.ino。這兩塊不需要連 Wi-Fi，也不用改帳密。
步驟 5：擺放與供電
• 主機放紅隊球門旁，節點放藍隊球門旁，開關板放天秤附近。
• 三塊都接上行動電源或 USB 電源。
• 開機順序不拘，節點和開關板會自己搜尋主機。
• 節點和開關板的板載藍燈（GPIO 2）亮起，代表已經連上主機。剛開機要等幾秒。
步驟 6：開啟網頁確認
手機或電腦連上和主機同一個 Wi-Fi，用瀏覽器開啟步驟 2 記下的網址：
• 裁判頁面：http://主機IP/referee
• 選手看板：http://主機IP/
裁判頁面上應該看到兩行綠燈：「藍隊感測節點：🟢 已連線」和「天秤開關板：🟢 已連線」。
驗收測試
1. 在裁判頁面按「開始比賽」，倒數開始。
2. 用手擋一下紅隊感測器，紅隊 +1。擋住不放，只會加一次。
3. 用手擋一下藍隊感測器，藍隊 +1。
4. 壓一次紅隊天秤開關，裁判頁面顯示「天秤 1/2」；再壓一次，顯示「×2 剩 10 秒」。
5. 加倍期間擋紅隊感測器，紅隊 +2；10 秒過後再擋，回到 +1。藍隊同理。
6. 按罰分、撤銷，確認次數正確。按「提前結算」，最終分數應為「得分 − 罰分」。
7. 拔掉藍隊節點的電源，約 3 秒後裁判頁面顯示離線；重新通電後會自動恢復。
日常使用
• 選手看板網址給大螢幕或投影用，只顯示分數和計時，剩 10 秒時計時變紅色。
• 裁判用裁判頁面操作。主按鈕會依狀態變成「開始比賽」、「提前結算」、「開始下一輪」。
• 「重設全部」會回到等待開始，並清空所有分數、罰分與天秤狀態。
• 罰分只在比賽進行中可以增減，結算時才會從得分扣除。
• 天秤加倍只在比賽進行中有效。加倍期間再按開關不計入，結束後重新從 0 開始數，可以再次觸發，不會疊加成 4 倍。
常見問題
裁判頁面一直顯示「離線」 最常見原因是 MASTER_MAC 填錯。重新對照步驟 2 序列埠印出的 MAC，修正後重新燒錄節點或開關板。
網頁打不開 確認手機和主機連同一個 Wi-Fi，而且是 2.4 GHz。部分公共 Wi-Fi 有「裝置隔離」功能，會讓裝置互相連不到，這種情況可以改用手機熱點或自備的分享器。
序列埠畫面一直重複出現 ets、rst、load 這些開機訊息 多半是供電不足。換一條短而好的 USB 線，或換電源。看到 Brownout detector 字樣就可以確定是供電問題。
行動電源用一陣子就自己斷電 有些行動電源在電流太小時會自動關閉，節點的耗電最低，最容易遇到。選有「小電流模式」或「常開模式」的行動電源，並先實測放一小時。
藍隊漏球或同一球加多次 用 FC-51 上的小旋鈕調整偵測距離，並確認感測器沒有被環境光或反光物影響。程式中的 SENSOR_ON_TIME 與 SENSOR_OFF_TIME 也可以微調。
天秤開關一次被算成好幾次 把開關板程式的 SWITCH_PRESS_TIME 與 SWITCH_RELEASE_TIME 調大，並檢查機構上開關的壓下是否為明確的一次動作。
換了主機板之後，節點和開關板都連不上 因為 MAC 不同了。重新做步驟 2、3、4。

給維護者的技術備註
• 節點和開關板用 ESP-NOW 單點傳送，有硬體確認；進球或按壓封包沒確認就每 10 毫秒重送，主機用流水號去除重複，所以不會重複計分。
• 主機連上路由器後才啟動 ESP-NOW，所以使用路由器的頻道。節點與開關板會自動從頻道 1 到 13 搜尋，失聯時會重新搜尋，路由器換頻道也能自動恢復。
• 封包格式在三個程式中必須一致：{magic 0xA5, type, seq}。type 為 1 進球（藍節點）、2 藍節點心跳、3 紅天秤按壓、4 藍天秤按壓、5 開關板心跳。
• 所有比賽邏輯（狀態機、計時、罰分、結算、天秤加倍）都在主機。節點永遠回報，主機只在比賽進行中才採計。
• 主機網站的 API：GET /api/score、GET /api/state、POST /api/start、/api/settle、/api/penalty、/api/reset。
• 本程式尚未在實體硬體上經過完整驗證，上線前請務必做完驗收測試。
